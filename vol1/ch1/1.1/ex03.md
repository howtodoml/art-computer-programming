# TAOCP Vol. 1, Section 1.1, Exercise 3 [20]

**Problem (paraphrased).** Rewrite Algorithm E so that it never does a plain copy like `m ← n`. Write the result in the same step-by-step style and call it Algorithm F.

## The idea

In Algorithm E, step E3 exists only to shuffle values: the old n moves into m, and r moves into n. Nothing new is computed there.

We can skip the shuffle by letting m and n take turns. Put each remainder straight back into the variable that was just divided. After that, the two variables have swapped roles, so the next division goes the other way. Two steps of F do the work of two trips through E's loop, and there's no copying at all.

## Algorithm F

Given two positive integers m and n, find their greatest common divisor.

**F1.** [Remainder m/n.] Divide m by n and let m be the remainder.

**F2.** [Is it zero?] If m = 0, the algorithm terminates with answer n.

**F3.** [Remainder n/m.] Divide n by m and let n be the remainder.

**F4.** [Is it zero?] If n = 0, the algorithm terminates with answer m. Otherwise go back to F1.

## Why it's correct

F does the same divisions as E, in the same order. The only difference is which variable each result lands in.

Pair them up. After F1, m holds the r that E1 would compute, and n holds the same n as in E. So F2 tests the same thing as E2 and gives the same answer.

If E keeps going, E3 sets m ← n, n ← r. In F those values are already sitting in n and m, just with the names swapped. F3 then divides n by m, which is exactly E1's division with E's m and n. F4 matches E2 again, with the answer in m because the names are swapped.

When F goes back to F1, the names match E's again. So F returns what E returns, which is gcd(m, n).

## What's saved

Each pass through E's loop does one division and three assignments: r ←, m ← n and n ← r. F does one division and one assignment per remainder. The number of divisions is the same, and F needs no variable r.
