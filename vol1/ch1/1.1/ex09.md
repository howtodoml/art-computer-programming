# TAOCP Vol. 1, Section 1.1, Exercise 9 [M30]

**Problem (paraphrased).** Take two computational methods, C1 = (Q1, I1, Ω1, f1) and C2 = (Q2, I2, Ω2, f2). Give a set-theoretic definition of "C2 simulates C1". The idea is that every computation of C1 is copied by C2, though C2 may take more steps and may carry extra information in its states. One example: C1 is Algorithm E and C2 is a machine-language program for it.

## Notation

For a function f from a set to itself, write f^[k] for f applied k times. So f^[0](q) = q, and f^[k+1](q) = f(f^[k](q)).

## Definition

C2 **simulates** C1 if there are three functions

- g : I1 → I2  (how to set C2 up for a given C1 input),
- h : Q2 → Q1  (how to read a C1 state off a C2 state),
- j : Q2 → {1, 2, 3, …}  (how many C2 steps make up one C1 step),

such that:

**(a)** For every x in I1, h(g(x)) = x.

**(b)** For every q in Q2, f1(h(q)) = h(f2^[j(q)](q)).

**(c)** For every q in Q2, h(q) is in Ω1 if and only if q is in Ω2.

## What each piece means

g says how to start C2 on a C1 input. For Algorithm E, it loads the program into memory and puts m and n into the right locations. Condition (a) says that nothing is lost in doing this: reading the starting state of C2 back through h gives the original input.

h is the "decoding" map. It looks at a full machine state and picks out the part that corresponds to a C1 state. For a program, it would read the variables m, n and r and use the program counter to tell which step of E we're on. h can map many C2 states to the same C1 state. That's what allows C2 to hold more information than C1: other registers, scratch memory and the program itself are all ignored by h.

j allows C2 to be slower. One step of C1 may take j(q) steps of C2, and j(q) can depend on the state. For example, a machine that finds a remainder by repeated subtraction needs more steps when the quotient is large. Since j(q) ≥ 1, C2 always moves forward.

Condition (b) is the heart of it. Decode q and take one C1 step, or run C2 for j(q) steps and then decode. Both routes must land on the same C1 state. In a picture:

```
        q  ──── f2, j(q) times ────▶  q′
        │                             │
        h                             h
        ▼                             ▼
      h(q) ──────── f1 once ───────▶ h(q′)
```

Condition (c) makes stopping match up. C2 is in an output state exactly when the decoded state is an output state of C1. So C2 can't stop early, and it can't keep going after C1 has finished.

Condition (b) applies to every state in Q2, not only the ones where a C1 step happens to begin. That's harmless. For a state in the middle of a long C1 step, choose h to give the C1 state that step started from, and let j count the steps left to finish it.

## The definition really does capture "mimics"

Take any input x in I1. Let x₀ = x, x₁, x₂, … be the computation of C1, so x_{k+1} = f1(x_k). Let q₀ = g(x), q₁, q₂, … be the computation of C2. Define times t₀ = 0 and t_{k+1} = t_k + j(q_{t_k}).

**Claim.** h(q_{t_k}) = x_k for every k.

**Proof by induction.** For k = 0, h(q₀) = h(g(x)) = x = x₀ by (a). If h(q_{t_k}) = x_k, then

h(q_{t_{k+1}}) = h(f2^[j(q_{t_k})](q_{t_k})) = f1(h(q_{t_k})) = f1(x_k) = x_{k+1}

using (b). ∎

So C2 passes through every state of C1's computation, in order, at times t₀ < t₁ < t₂ < …, possibly with other steps in between.

**Termination matches too.** Suppose C1 stops after k steps, so x_k is in Ω1. By the claim, h(q_{t_k}) is in Ω1, so q_{t_k} is in Ω2 by (c). C2 has stopped, and h of its output is C1's output.

Now suppose C2 reaches Ω2 at some time T. Output states are fixed by f2, so C2 stays in Ω2 from then on. The times t_k increase without bound, so some t_k ≥ T. Then q_{t_k} is in Ω2, and by (c), x_k = h(q_{t_k}) is in Ω1. So C1 stops as well.

## A worked example

`ex09.py` builds a concrete case.

C1 is Algorithm E written as a computational method, with states (m, n), (m, n, r, k) for steps k = 1, 2, 3, and output states (n).

C2 is a small register machine with a program counter and registers M, N, R. It has no division. It computes the remainder by subtracting N from R until R < N. So one C1 step can take many C2 steps.

The script defines g, h and j for this pair. Then it checks (a) on every input with m, n ≤ 25. It checks (b) and (c) on every C2 state those inputs reach. Finally it runs both machines side by side and confirms the claim above: C2, decoded through h at the times t_k, follows C1 step for step and ends on gcd(m, n).

Two of the choices in that example are worth a look:

- **States in the subtraction loop.** Here h gives the state (M, N, R, 1), and j(q) = ⌊R/N⌋ + 1, the number of subtractions left plus the exit test.
- **The state between M ← N and N ← R.** The original m is gone by then, so h can't reconstruct the true C1 state. It doesn't need to. The next C1 step, (m, n, r, 3) → (n, r, r, 1), never reads m, so h can put any value there and (b) still holds.
